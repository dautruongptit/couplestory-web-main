6. SQL Injection

Cái này không nên ghi đơn giản là "chống SQL Injection".

Hãy làm thành một Security Checklist:

Security
├── SQL Injection
├── XSS
├── CSRF
├── Authentication bypass
├── Authorization / IDOR
├── File upload security
├── Path traversal
├── Rate limiting
├── Brute force
├── Session security
└── Sensitive data exposure

Đặc biệt CoupleStory có:

/public/{slug}

và:

/story/{id}
/event/{id}
/photo/{id}

thì cần kiểm tra IDOR / ownership rất kỹ.

Ví dụ:

User A

GET /api/stories/123

không được phép xem:

Story 123 thuộc User B

Đây thậm chí có thể quan trọng hơn SQL Injection trong hệ thống của bạn.

7. 🔐 Một user chỉ có 1 session

Mình đồng ý, nhưng không nên hiểu là:

"1 user chỉ được mở 1 tab."

Browser có thể có nhiều tab nhưng dùng chung một session.

Thứ bạn thực sự muốn là:

1 User chỉ có 1 ACTIVE EDITING SESSION.

Ví dụ:

User
 │
 └── Login Session
       │
       └── Active Story Editing Session

User mở:

Tab A → Edit Story 123

Tab B:

Edit Story 123

→ Backend phải phát hiện.

Có thể hiển thị:

⚠️ Story đang được chỉnh sửa

Câu chuyện này đang được chỉnh sửa
ở một cửa sổ khác.

[Tiếp tục ở đây]

Hoặc đơn giản hơn:

Another editing session is active.
[Take over]
Mình không khuyên logout toàn bộ khi mở tab thứ 2.

Vì:

Chrome Tab A
Chrome Tab B

thực chất có thể dùng cùng authentication session.

Bạn cần editing lock, không phải "browser tab lock".
